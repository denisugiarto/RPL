01 // Pengenalan

Apa itu Git?

Git adalah sistem pelacak perubahan pada file. Bayangkan Git seperti "mesin waktu" untuk kode-mu!

Tanpa Git

File berantakan dengan nama seperti:

📄 tugas.txt
📄 tugas_v2.txt
📄 tugas_fix.txt
📄 tugas_final.txt
📄 tugas_FINAL_banget.txt
📄 tugas_jadi_ini.txt

Dengan Git

Cukup satu file, semua versi tercatat rapi:

📝 tugas.txt
├── v1: "versi awal"
├── v2: "tambah gambar"
├── v3: "perbaiki typo"
└── v4: "versi final" ✨
💡 ANALOGI KEHIDUPAN

Git itu seperti fitur "Save" di game.
Saat main game, kamu bisa save progress. Kalau kalah, kamu bisa load save terakhir. Git melakukan hal yang sama untuk kode-mu — kamu bisa "kembali ke masa lalu" kapan saja kamu mau!

02 // Manfaat

Kenapa Harus Belajar Git?

4 alasan kuat mengapa Git adalah skill wajib buat programmer masa kini.

Melacak Perubahan

Tahu persis kapan, siapa, dan apa yang berubah di setiap baris kode.

Kolaborasi Tim

Bekerja bareng teman tanpa saling timpa kode. Semua kontribusi tercatat rapi.

Backup Otomatis

Kode aman tersimpan di server. Laptop rusak? Tenang, kode tetap aman!

Eksperimen Bebas

Coba ide gila tanpa takut rusak. Kalau gagal, balik ke versi sebelumnya dengan mudah.

🌟 FUN FACT

90% perusahaan teknologi di dunia menggunakan Git untuk mengelola kode mereka. Dari Google, Facebook, sampai startup kecil — semua pakai Git! Jadi, belajar Git = investasi masa depan. 🚀

03 // Kosakata Git

Istilah Penting dalam Git

5 istilah yang wajib kamu kuasai dulu sebelum mulai ngoding dengan Git.

repository

Repository

Folder khusus berisi semua file proyek + riwayat perubahannya.

💡 Sepelin "brankas proyek" yang mencatat semua kejadian

commit

Commit

Menyimpan snapshot (foto) perubahan kode ke dalam repository.

💡 Seperti "save game" di video game

branch

Branch

Cabang paralel untuk mengembangkan fitur tanpa ganggu branch utama.

💡 Seperti "dimensi alternatif" untuk proyekmu

push/pull

Push & Pull

Push: kirim kode ke server. Pull: ambil kode terbaru dari server.

💡 Seperti "kirim & terima email" kode

merge

Merge

Menggabungkan perubahan dari satu branch ke branch lain.

💡 Seperti "menyatukan dua sungai" jadi satu

mnemonic

Ingat: Repository → Commit → Branch → Merge → Push
Itu siklus hidup Git!

06 // Perintah Dasar

Perintah Sakti Git

6 perintah dasar yang akan sering kamu gunakan sehari-hari.

bash — perintah-dasar
# 1. Buat repository baru
$ git init
Initialized empty Git repository
# 2. Cek status perubahan
$ git status
On branch main
Untracked files: index.html
# 3. Tandai perubahan siap disimpan
$ git add index.html
# atau semua file: git add .
# 4. Simpan dengan pesan
$ git commit -m "menambah halaman utama"
[main abc1234] menambah halaman utama
bash — perintah-dasar
# 5. Lihat riwayat commit
$ git log
commit abc1234...
Author: Budi <budi@email.com>
Date: Mon Jan 15 10:30:00
menambah halaman utama
# 6. Kirim ke server (GitHub)
$ git push origin main
Enumerating objects: 5, done.
To github.com:budi/project.git
# Bonus: ambil update dari server
$ git pull
Already up to date.
git init

Mulai proyek baru, sekali seumur hidup proyek

git add + commit

Duo sakti: lakukan berulang setiap ada perubahan

git push

Kirim ke cloud, lakukan setelah commit

07 // Studi Kasus

Praktik: Membuat Website Portofolio

Mari ikuti kisah Andi yang membuat website portofolio pertamanya dengan Git!

1
Mulai proyek

Andi membuat folder portofolio dan menjalankan git init

2
Buat file index.html

Andi menulis HTML dasar lalu git add . dan git commit -m "versi awal"

3
Tambah CSS

Andi menambah style.css, commit lagi: "tambah styling"

4
Push ke GitHub

Andi git push agar teman bisa lihat hasilnya di GitHub

andi@laptop — portofolio
$ mkdir portofolio && cd portofolio
$ git init
✓ Initialized Git repository
# Andi membuat index.html
$ git status
?? index.html
$ git add index.html
$ git commit -m "versi awal portofolio"
✓ [main abc123] versi awal
1 file changed, 15 insertions
# Andi tambah CSS
$ git add style.css
$ git commit -m "tambah styling"
✓ [main def456] tambah styling
# Kirim ke GitHub
$ git push origin main
✓ Pushed to GitHub! 🎉
💡 PESAN MORAL

Andi tidak pernah kehilangan kode! Kalau besok CSS-nya rusak, dia bisa kembali ke "versi awal" dengan mudah. Itulah kekuatan commit yang rutin! 💪

08 // Kolaborasi

Branch: Bekerja Rame-rame

Bagaimana tim developer mengerjakan fitur berbeda tanpa saling ganggu? Pakai branch!

🌳 Visual Branch

bash — branch-commands
# Buat branch baru
$ git branch feature/login
# Pindah ke branch tersebut
$ git checkout feature/login
Switched to branch 'feature/login'
# Atau keduanya sekaligus:
$ git checkout -b feature/login
# Setelah selesai, merge ke main
$ git checkout main
$ git merge feature/login
✓ Merge berhasil!
👥 ANALOGI TUGAS KELOMPOK

Bayangkan mengerjakan tugas kelompok: Budi nulis bab 1, Siti nulis bab 2, Agus nulis bab 3.
Mereka kerja di "branch" masing-masing. Setelah selesai, semua bab digabung (merge) jadi satu dokumen utuh. Tidak ada yang saling timpa kerjaan! ✨
