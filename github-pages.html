TUTORIAL PRAKTIK RPL - KELAS X Lanjutan Git

Deploy Website
dengan GitHub Pages

Ubah repository Git kamu menjadi website gratis yang bisa diakses semua orang lewat internet. Tanpa server, tanpa biaya, cukup beberapa klik!

01 // Pengenalan

Apa itu GitHub Pages?

Layanan gratis dari GitHub untuk mengubah repository menjadi website yang bisa diakses di internet.

Apa yang bisa dibuat?

📄 Halaman statis (HTML, CSS, JS)
👤 Website portofolio pribadi
📚 Dokumentasi proyek
🎨 Landing page / blog sederhana

Kelebihan utama

✅ 100% gratis dan tanpa biaya server

✅ Deploy otomatis saat kamu push

✅ HTTPS (aman) otomatis aktif

✅ Domain gratis: username.github.io

💡 ANALOGI

GitHub Pages itu seperti pura-pura "memajang hasil kerajinanmu di etalase toko".
Kode yang tadinya cuma tersimpan di repository (di gudang), sekarang dipajang di etalase (internet) agar siapa saja bisa datang melihat dan mengaksesnya.

02 // Prasyarat

Yang Harus Disiapkan

Sebelum deploy, pastikan 3 hal ini sudah ada. Kalau belum, selesaikan dulu ya!

Repository di GitHub

Proyek yang sudah kamu push ke GitHub (dari materi Git di VS Code).

File index.html

File utama website. GitHub Pages secara otomatis menampilkan file yang bernama index.html ini.

Perubahan Sudah di-commit

Pastikan semua file sudah kamu commit dan push ke branch main.

⚠️ PERHATIAN: Nama file utama HARUS index.html. Kalau namanya beda (misal index2.html atau beranda.html), website tidak akan tampil otomatis saat dibuka.
03 // Cara 1 - Manual

Aktifkan lewat Settings

Cara paling mudah dan cukup dilakukan sekali. Mari aktifkan GitHub Pages dari menu Settings repository.

1
Buka repository di GitHub

Masuk ke github.com → buka repository proyekmu.

2
Klik menu Settings

Tab Settings paling kanan di baris menu repository.

3
Klik menu Pages

Di sidebar kiri, cari dan klik Pages (bagian "Code and automation").

4
Pilih branch lalu Save

Atur "Source" ke Deploy from a branch, pilih branch main, folder / (root), lalu klik Save.

github.com/kamu/proyek-pertamaku → Settings → Pages
Build and deployment
Source:
● Deploy from a branch
Branch:
main / (root)
[ Save ]
# Setelah save, tunggu 1-2 menit.
# Pesan sukses muncul:
✓ Your site is published at
https://username.github.io/proyek-pertamaku/
04 // URL

Format Alamat Website

Setiap repository mendapat alamat unik. Pahami pola-nya supaya bisa menebak dan membaginya.

Rumus URL GitHub Pages
# Website biasa:
https://username.github.io/nama-repositori/
# Contoh nyata:
https://andra.github.io/portofolio/
# Repository khusus username.github.io:
https://username.github.io
# (repo pertama itu = website utama, tanpa nama repositori)
https://username.github.io/proyek-pertamaku/
🌐
Halo Git!
Ini halaman index.html-mu yang sudah live di internet! 🎉
🧠 INGAT

Alamat website = alamat rumah rumahmu.
Kalau rumah (repository) bernama portofolio, alamatnya username.github.io/portofolio/. Ganti bagian 'portofolio' dengan nama repository-mu!

05 // Update

Updates Website Setiap Push

Inilah bagian terbaiknya — setiap kamu push perubahan, website akan update otomatis tanpa perlu konfigurasi ulang!

workflow — update rutin
# 1. Edit kode di VS Code, lalu commit & push seperti biasa:
$ git add .
$ git commit -m "ganti warna header"
$ git push
# 2. Atau lewat VS Code: klik Sync Changes (🔄).
✓ Pushed to GitHub — website sedang deploy…
✓ Your site is up to date!
06 // Verifikasi

Lihat Status Deployment

Bagaimana tahu proses deploy sukses atau masih berjalan? Cek dari tab Actions di GitHub.

1
Buka tab Actions

Di repository, klik tab Actions untuk melihat perjalanan deploy.

2
Cari status symbol

✅ hijau = sukses • 🟠 kuning = proses • ❌ merah = gagal.

3
Klik detail untuk melihat log

Bisa melihat detail langkah deploy. Kalau ada error, informasi di sini bisa membantu memperbaiki.

07 // Otomatis

Deploy Otomatis Dengan Workflow

Di materi lanjut, kamu bisa mengotomatiskan deploy hingga auto setiap push. Cara di atas (Settings) sudah cukup untuk pemula — ini sebagai informasi bonus.

Kenapa memakai Workflow?

Dengan GitHub Actions, kamu bisa menjalankan perintah build (misalnya mengcompile proyek JavaScript) otomatis sebelum website di-publish. Cocok untuk proyek yang lebih kompleks.

.github/workflows/static.yml (contoh)
# Cara alternatif & sering dipakai projek
# kompleks. Untuk pemula, gunakan cara
# "Settings → Pages" di slide sebelumnya.
- uses: actions/checkout@v4
- uses: actions/upload-pages-artifact@v3
- uses: actions/deploy-pages@v4
🔧 SARAN: Untuk mata pelajaran ini, cukup gunakan cara pertama (Settings → Pages) yang jauh lebih simpel. Materi otomatis ini hanya untuk menambah wawasan bahwa GitHub Pages bisa diprogram dengan GitHub Actions.
08 // Solusi

Masalah yang Sering Terjadi

Website tidak muncul? Tenang, berikut solusinya dalam sebagian besar kasus.

🔎

Website kosong / 404

Belum ada index.html, atau nama file beda. Atau deploy masih butuh waktu 1-2 menit. Cek di tab Actions.

🔗

Alamat salah / tidak bisa dibuka

Cek kembali format username.github.io/nama-repo/. Username = nama akun GitHubmu (huruf kecil).

📁

Lokasi folder salah

Kalau file website ada di subfolder, atur "Folder" di setting Pages ke nama folder tersebut, bukan / (root).

⏳

Perubahan belum muncul

Pastikan kamu benar-benar push (bukan cuma commit lokal), lalu refresh halaman dengan paksa Ctrl+Shift+R.

💡 GOLDEN RULE: Kalau bingung, selalu bawal ke tab Actions di repository. Di situlah tanda sukses/gagalnya deploy. Salin pesan errornya lalu cari solusinya.
